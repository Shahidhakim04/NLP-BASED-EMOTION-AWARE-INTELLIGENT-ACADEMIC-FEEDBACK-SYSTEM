================================================================================
1. PROJECT OVERVIEW
================================================================================

This project is an AI-powered, NLP-driven web application designed to evaluate
student academic answers from two distinct angles:

  (1) EMOTIONAL INTELLIGENCE  — Detecting the emotional tone embedded in a
      student's written response (joy, sadness, fear, anger, surprise, disgust,
      or neutral) using a pre-trained transformer-based classification model.

  (2) WRITING QUALITY ANALYSIS — Measuring the structural, linguistic, and
      academic quality of the answer across five weighted dimensions: length,
      complexity, vocabulary richness, readability, and organization/structure.

The result is a comprehensive, personalized feedback report that tells the
student not just what was wrong, but ALSO how they emotionally approached the
task — bridging the gap between cognitive and affective dimensions of learning.

The system is built for academic contexts such as classroom assignments, online
assessments, and self-study evaluation tools. It also tracks each student's
performance over multiple sessions through a persistent progress dashboard.


================================================================================
2. SYSTEM ARCHITECTURE
================================================================================

The application follows a modular, pipeline-based architecture:

  [Student Input (Text Answer)]
          |
          v
  [preprocess.py]               -- Text normalization & cleaning
          |
          v
  [emotion_model.py]            -- Emotion classification via Transformer model
          |
          v
  [advanced_quality_analyzer.py]-- 5-dimensional quality scoring
          |
          v
  [topic_detector.py]           -- Academic subject identification
          |
          v
  [enhanced_feedback_generator.py] -- Context-aware personalized feedback
          |
          v
  [progress_tracker.py]         -- Session persistence & trend computation
          |
          v
  [Flask App (app_enhanced.py)] -- Route handling & template rendering
          |
          v
  [HTML Templates]              -- Glassmorphism UI presented to student


The Flask web server acts as the central orchestrator. On each POST request it
triggers the entire pipeline sequentially and passes all results to the Jinja2
HTML templates for rendering.

3. CORE MODULES — DETAILED DESCRIPTION
================================================================================

------------------------------------------------------------------------
3.1  preprocess.py  — Text Preprocessor
------------------------------------------------------------------------

Purpose:
  Normalizes raw student input before it is fed into the NLP models.

What it does:
  - Converts the entire text to lowercase.
  - Strips all non-alphabetic characters (numbers, punctuation, symbols)
    using a regex substitution: re.sub(r"[^a-zA-Z\s]", "", text)

Why this matters:
  Transformer models are sensitive to token distribution. Removing noise
  ensures the emotion classifier focuses on the semantic and linguistic
  patterns rather than formatting artifacts. This is applied before emotion
  detection but NOT before quality analysis (since quality analysis requires
  the raw text to measure punctuation, capitalization, etc.).


------------------------------------------------------------------------
3.2  emotion_model.py  — Emotion Detection Engine
------------------------------------------------------------------------

Purpose:
  Classifies the detected emotion(s) present in the student's writing.

Model Used:
  j-hartmann/emotion-english-distilroberta-base
  (Available on HuggingFace Model Hub)

  - Architecture: DistilRoBERTa (a distilled version of RoBERTa)
  - Task:         Multi-class text classification
  - Output:       Probability scores for 7 emotion classes
  - Emotion Classes:
      joy, sadness, fear, anger, surprise, disgust, neutral

How it works:
  - Uses HuggingFace's pipeline() API with "text-classification" task.
  - The `return_all_scores=True` flag ensures ALL 7 emotion scores are
    returned (not just the highest one).
  - Results are sorted in descending order of confidence score.
  - The top 6 emotions (with their percentage scores) are passed to the
    frontend for the emotion distribution visualization.

Key function:
  detect_emotion(text) -> list of dicts [{label, score}, ...]


------------------------------------------------------------------------
3.3  advanced_quality_analyzer.py  — Multi-Dimensional Quality Scorer
------------------------------------------------------------------------

Purpose:
  Evaluates the academic writing quality of the submitted answer across
  five measurable and weighted dimensions.

Class: AdvancedQualityAnalyzer

Scoring Weights:
  - Length       : 20%
  - Complexity   : 25%
  - Vocabulary   : 25%
  - Readability  : 15%
  - Structure    : 15%

Dimensions Explained:

  [A] LENGTH SCORE (20%)
      Measures number of words in the answer:
        < 20 words  → Score: 20  (Too short, unacceptable)
        20-49 words → Score: 50  (Below average)
        50-99 words → Score: 75  (Good)
        100-199 words → Score: 90 (Very good)
        200+ words  → Score: 100 (Excellent)

  [B] COMPLEXITY SCORE (25%)
      Measures the average number of words per sentence:
        < 8 words/sentence   → Score: 40  (Too simple)
        8-14 words/sentence  → Score: 70  (Good)
        15-24 words/sentence → Score: 90  (Very good / Ideal)
        25+ words/sentence   → Score: 75  (May be too convoluted)

  [C] VOCABULARY SCORE (25%)
      Measures lexical diversity (unique word ratio):
        Formula: unique_words / total_words × 120 (capped at 100)
      A higher ratio indicates richer vocabulary usage and less repetition.

  [D] READABILITY SCORE (15%)
      Uses the Flesch Reading Ease formula from the `textstat` library:
        Score < 30  → Very difficult → Quality: 50
        Score 30-49 → Difficult      → Quality: 70
        Score 50-69 → Good academic  → Quality: 90
        Score 70-79 → Fairly easy    → Quality: 85
        Score 80+   → Too simple     → Quality: 70
      The ideal academic writing sits in the 50-70 Flesch range.

  [E] STRUCTURE SCORE (15%)
      Checks for four structural indicators:
        + Multiple paragraphs (line breaks)       → +30 points
        + Proper sentence capitalization (>70%)   → +25 points
        + Adequate punctuation usage (>2 marks)   → +25 points
        + Transitional phrases present            → +20 points
          (e.g., "however", "therefore", "furthermore",
                 "moreover", "consequently", "for example",
                 "in conclusion")
      Maximum: 100 points (capped)

Final Output:
  overall_score    (0-100 weighted composite)
  quality_level    (poor / below_average / average / good / excellent)
  word_count       (raw count)
  sentence_count   (raw count)
  All 5 individual dimension scores


------------------------------------------------------------------------
3.4  topic_detector.py  — Academic Subject Identifier
------------------------------------------------------------------------

Purpose:
  Automatically identifies the academic subject/domain of the student's
  answer so that feedback can be contextualized appropriately.

Supported Academic Topics (20 total):
  Mathematics, Physics, Chemistry, Biology, Computer Science, Programming,
  History, Literature, English Language, Economics, Psychology, Philosophy,
  Engineering, Medicine, Geography, Political Science, Sociology, Business,
  Statistics, Data Science

Detection Methods:

  [PRIMARY] ML-Based (Zero-Shot Classification):
    - Model: facebook/bart-large-mnli
    - Method: Zero-shot classification — classifies text into topic labels
      without task-specific training.
    - Returns: primary topic, confidence score, top-5 topic scores.
    - Note: Disabled by default (use_ml=False) for performance reasons.

  [FALLBACK] Keyword-Based Detection:
    - Fast, deterministic keyword matching for each topic.
    - Each topic has ~12 domain-specific keywords.
    - Computes a match-count score per topic, normalizes it, and ranks them.
    - Example keywords for "Computer Science":
        algorithm, data structure, programming, code, function, variable,
        loop, array, database, software, binary
    - Returns: primary_topic, confidence, all_topics (top 5)

Additional:
  get_topic_emoji(topic) → Returns an emoji icon for the detected topic
  (e.g., Physics → ⚛️, Biology → 🧬, Computer Science → 💻)


------------------------------------------------------------------------
3.5  enhanced_feedback_generator.py  — Personalized Feedback Engine
------------------------------------------------------------------------

Purpose:
  Synthesizes all analysis outputs (emotion, topic, quality metrics) into
  a natural-language, personalized, multi-part feedback paragraph.

Feedback Structure (5 parts assembled and joined):

  [Part 1] EMOTION OPENING
    Generates an opening sentence based on the detected emotion and its
    confidence level. Two variants exist: high confidence (>0.8) and low.
    Example (joy, high confidence):
      "Your response radiates enthusiasm and positive engagement with the
      topic! This positive mindset is excellent for learning."

  [Part 2] TOPIC ACKNOWLEDGMENT
    If topic confidence > 0.7 → Strong acknowledgment
    If topic confidence > 0.4 → Mild acknowledgment
    Else                      → Generic comment

  [Part 3] QUALITY FEEDBACK
    Translates numeric quality scores into readable sentences:
    - Overall score categorization
    - Specific feedback on length if it's too short
    - Sentence complexity commentary
    - Vocabulary richness assessment
    - Readability level note
    - Structural organization comment

  [Part 4] IMPROVEMENT SUGGESTIONS
    Generates actionable advice:
    - "Focus on expanding your explanation with specific examples..."
    - "Use transitional words like 'however,' 'therefore,'..."
    - "Incorporate subject-specific terminology..."
    - Emotion-specific advice (e.g., for fear/sadness → "Break down complex
      problems into smaller, manageable parts.")

  [Part 5] ENCOURAGING CONCLUSION
    Score-based conclusion:
      ≥ 80 → "Keep up the excellent work! Your understanding is clearly strong."
      ≥ 60 → "You're on the right track. Keep refining your approach!"
      < 60 → "Keep practicing! Every attempt helps you improve."
    With emotion-specific suffix for sadness/fear/joy.


------------------------------------------------------------------------
3.6  progress_tracker.py  — Session-Based Progress Logger
------------------------------------------------------------------------

Purpose:
  Tracks each student's submission history and computes performance trends
  over multiple uses of the application within the same browser session.

Storage Mechanism:
  - All data is persisted as JSON in: data/progress.json
  - Each student is identified by a UUID generated per Flask session.
  - Data survives server restarts (file-based, not in-memory).

Data Stored Per Submission:
  - timestamp (ISO format)
  - submission_id (sequential)
  - answer snippet (first 500 characters)
  - detected emotion
  - confidence score
  - all quality metrics (all 5 dimension scores + overall)
  - topic information (primary topic, confidence)
  - word count

Aggregated Statistics Computed:
  - total_submissions count
  - average_quality score (running average)
  - most_common_emotion (mode of all detected emotions)
  - improvement_trend ("improving" or "declining" based on last 5 submissions)

Progress Summary Output:
  - Emotion distribution (counts per emotion)
  - Quality progression array (score per submission for charting)
  - Topic distribution (counts per detected topic)
  - Latest submission details
  - First and latest submission dates

Additional Capabilities:
  - delete_student_data(student_id) → Reset/clear all history
  - get_all_students() → List all tracked student UUIDs


------------------------------------------------------------------------
3.7  app_enhanced.py  — Flask Web Application (Main Entry Point)
------------------------------------------------------------------------

Purpose:
  Central request handler that orchestrates the full analysis pipeline
  and serves HTML pages.

Routes:

  GET  /           → Renders index.html (input form)
  POST /           → Triggers full pipeline, renders results.html
  GET  /progress   → Renders progress.html with session's history data
  GET  /api/progress → JSON API returning progress_summary (for AJAX)
  POST /reset-progress → Clears current session's data and UUID

Session Management:
  - Each browser session is assigned a UUID (student_id) stored in
    Flask's session cookie.
  - This UUID is used as the key in progress.json for per-student tracking.
  - The secret key for signing sessions is: 'your-secret-key-here-change-in-production'
    (Should be replaced with a secure random string in production.)

Pipeline Execution per POST:
  1. Preprocess raw text
  2. Run emotion detection → get top 6 emotions with scores
  3. Run quality analysis → compute all 5 metrics + overall score
  4. Run topic detection (keyword mode) → get primary topic + emoji
  5. Generate enhanced feedback paragraph
  6. Log submission to progress_tracker
  7. Render results.html with all gathered data

Error Handling:
  On exception → Falls back to neutral emotion, 50% confidence, 50 quality
  score, and a generic error message. Server continues running.

5. AI/ML MODELS USED
================================================================================

  Model 1: j-hartmann/emotion-english-distilroberta-base
    Task:          Text Classification (Emotion Detection)
    Architecture:  DistilRoBERTa (distilled BERT-like transformer)
    Labels:        anger, disgust, fear, joy, neutral, sadness, surprise
    Framework:     HuggingFace Transformers + PyTorch
    Inference:     CPU or GPU (auto-detected by PyTorch)

  Model 2: facebook/bart-large-mnli (Optional, disabled by default)
    Task:          Zero-Shot Text Classification (Topic Detection)
    Architecture:  BART (Bidirectional and Auto-Regressive Transformers)
    Usage:         Classifies text into 20 academic topic labels without
                   task-specific training using NLI (Natural Language
                   Inference) as the underlying mechanism.
    Status:        use_ml=False (keyword fallback used for speed)

  Library: textstat
    Purpose:       Computes the Flesch Reading Ease score for readability
                   analysis (one of the 5 quality dimensions).

7. DATA FLOW — STEP BY STEP
================================================================================

  STEP 1: Student visits http://localhost:5000/
          → Flask checks for session UUID (creates one if missing)
          → Serves index.html

  STEP 2: Student types an academic answer and clicks "Run Deep Analysis"
          → Form submits via POST to /

  STEP 3: Flask receives raw text
          → preprocess_text() called → lowercase, remove non-alpha chars

  STEP 4: Preprocessed text passed to detect_emotion()
          → HuggingFace model classifies into 7 emotions
          → Results sorted by score, top 6 extracted

  STEP 5: Raw (unprocessed) text passed to quality_analyzer.analyze_quality()
          → Five dimensions computed independently
          → Weighted overall score computed
          → quality_level string determined (poor → excellent)

  STEP 6: Raw text passed to detect_topic(use_ml=False)
          → Keyword matching across 12 topics × ~12 keywords each
          → Primary topic selected, emoji fetched

  STEP 7: All results passed to generate_enhanced_feedback()
          → 5-part natural language paragraph assembled

  STEP 8: Submission data logged via progress_tracker.log_submission()
          → Data appended to data/progress.json under student's UUID
          → Statistics recomputed and file saved

  STEP 9: Flask renders results.html with all data
          → Student sees: emotion, confidence, 5 quality scores, topic,
            feedback paragraph, and emotion distribution

  STEP 10: Student can navigate to /progress
          → progress_tracker.get_progress_summary() called
          → Progress dashboard rendered with all historical data

10. KEY DESIGN DECISIONS & TECHNICAL NOTES
================================================================================

  [1] SESSION-BASED STUDENT TRACKING
      The system uses Flask sessions (cookie-based) to assign each browser
      a unique UUID. This means each browser tab/device is treated as one
      "student." This is suitable for demo/prototype use. In production,
      a proper user authentication system should replace this.

  [2] KEYWORD-BASED TOPIC DETECTION (DEFAULT)
      The ML-based topic detection (BART zero-shot) is powerful but slow.
      It is disabled by default (use_ml=False) to ensure fast response times.
      The keyword fallback is nearly instant and sufficient for most common
      academic topics.

  [3] PREPROCESSING ONLY FOR EMOTION MODEL
      Quality analysis intentionally uses the raw (unprocessed) text because
      quality metrics depend on capitalization, punctuation, and structure —
      all of which are removed during preprocessing. Preprocessing is only
      applied before the emotion classifier.

  [4] ERROR RESILIENCE
      The main route wraps the entire pipeline in a try-except block.
      If any model or module fails (e.g., model not downloaded, OOM error),
      the system falls back to neutral emotion, default quality, and a
      generic error message, keeping the app alive.

  [5] JSON FILE-BASED PERSISTENCE
      Progress data is stored in a flat JSON file (data/progress.json).
      This is simple and portable but not suitable for multi-user production
      deployments. A database (SQLite, PostgreSQL) should be used instead.

  [6] GLASSMORPHISM UI
      All UI styling is written in pure Vanilla CSS (no frameworks).
      Focus on immersive visual design: dark theme, glowing gradients,
      animated backgrounds, frosted glass panels, and smooth transitions
      to create a premium, modern feel.
